# Исправления безопасности: 13 сентября 2026

Закрыты находки 1, 2, 3, 5, 6, 7, 8 и 9 из [исходного аудита](SECURITY-AUDIT-2026-09-13.md).
HTTP и публикация портов 80/8080 на всех интерфейсах оставлены без изменений по запросу владельца.
Это не устраняет риск перехвата токена и паролей на участке браузер -> приложение.

## Что изменилось

| Находка | Исправление |
|---|---|
| 1. Открытое администрирование, передача IMAP-пароля другому серверу | Обязательный токен; смена IMAP-хоста, порта или пользователя требует повторного ввода пароля. Сохранённый пароль привязан к назначению; частично неуспешное сохранение не переносит его на другое назначение |
| 2. Открытые данные и синхронизация | Все `/api` и `/api/*` защищены общим ASGI middleware, кроме минимального `GET /api/live`. Обе страницы используют общий клиент с токеном. Добавлены ограничения частоты ручных запусков |
| 3. Отключение защиты при ошибке секретов | Повреждённый или нечитаемый JSON закрывает API с HTTP 503; запись запрещена до локального восстановления. Отсутствующий токен также закрывает API |
| 5. Уязвимая Starlette | FastAPI 0.141.1 и Starlette 1.6.0; полные runtime/dev lock-файлы с хешами, обязательная проверка хешей при сборке |
| 6. Совпадение отправителя по подстроке | Полный адрес либо домен с поддоменами сравнивается с адресом в `From`. Display name и результат IMAP SEARCH не подменяют эту проверку |
| 7. Неограниченная обработка писем/PDF | Лимиты входа, количества частей/писем, извлекаемого текста, памяти процесса и ресурсов контейнера; превышения диагностируются, неполные чеки не принимаются как успешно разобранные |
| 8. JSON разбирался до авторизации | Аутентификация до чтения тела; общий предел 64 KiB и 10 секунд, включая запросы без Content-Length |
| 9. Права временного файла секретов | Временный файл создаётся через `mkstemp` сразу с 0600, затем flush/fsync и атомарная замена. При ошибке временный файл удаляется |

Дополнительно: контейнер работает не от root (UID/GID 10001), без capabilities, с `no-new-privileges`
и read-only корневой файловой системой. Chart.js закреплён SRI-хешем; API-ответы не кешируются,
добавлены `nosniff`, запрет фреймов и `no-referrer`. Встроенные Swagger/ReDoc/OpenAPI отключены.

## Обновление существующей установки

1. Остановите старый контейнер. Сделайте отдельную защищённую копию `data` и `.env`.
2. Сохраните существующий `ADMIN_TOKEN`. Если его нет, локально создайте токен командой
   `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'` и задайте его в `.env`; права `.env` должны быть 0600.
   Сохранённый в `data/secrets.json` токен имеет приоритет над окружением. Существующие короткие токены
   пока работают для совместимости, но их следует заменить. Новый токен: минимум 32 печатных ASCII-символа без пробелов.
3. На Linux выполните `sudo chown -R 10001:10001 data` и `sudo chmod 700 data`.
   Старые файлы и резервные копии также должны быть закрыты от посторонних: `sudo chmod -R go-rwx data`.
4. Выполните `docker compose up -d --build`. Проверьте `GET /api/live`, затем войдите с токеном на `/settings`.
   Для внешнего мониторинга деталей `/api/health` и автоматизации синхронизации теперь нужен `X-Admin-Token`.
5. Проверьте правила магазинов: произвольные подстроки больше не допустимы, используйте адреса или домены.
   Старое правило `maxima` автоматически интерпретируется как `maxima.lt`. Другие неоднозначные правила требуют правки.
6. При смене IMAP-хоста/порта/ящика введите пароль снова. Если секретный файл повреждён, восстановите его локально
   и перезапустите приложение. Не удаляйте его ради обхода ошибки: это может активировать старые значения из окружения.

В новых файлах секретов есть внутреннее поле `_IMAP_IDENTITY`. Старые версии кода его не учитывают;
откат приложения без отдельной проверки настроек не сохраняет новые гарантии безопасности.
Удалить административный токен через UI/API нельзя; сброс к окружению разрешён только при наличии подходящего токена там.
Для пароля почты и ключа Claude действия очистки/сброса сохранены.

## Лимиты

- Тело HTTP-запроса: 64 KiB, 10 секунд. Неверный токен: 20 ответов 401 за минуту на адрес клиента, далее 429.
- Проверка IMAP: 5 запусков за 10 минут; ручная синхронизация: 5 за минуту; пересборка: 2 за 10 минут.
- Письмо: 10 MiB; вложение: 5 MiB; суммарно декодированный контент письма: 10 MiB; до 100 MIME-частей и 10 вложений.
- PDF: до 40 страниц, 2 MiB распакованного потока страницы, 60 000 символов суммарного PDF-текста письма.
- Один проход IMAP: до 2 000 совпавших писем и 64 MiB полученных данных. При превышении уменьшите окно синхронизации;
  автоматическая обрезка результата и фиксация неполной пересборки не выполняются.
- Linux sync worker: 768 MiB адресного пространства; Compose: 1 GiB памяти, 1 CPU, 64 процесса.
  Вне Docker задайте ограничения CPU/памяти средствами ОС. На macOS лимит адресного пространства не применяется.

## Оставшиеся ограничения

- HTTP остаётся незашифрованным. Наличие токена и SRI не защищает от активной подмены HTML на таком соединении.
- Сохранённый IMAP-хост является доверенной административной настройкой. Проверка DNS в `test-imap` не привязывает
  адрес к фактическому соединению и не является полноценной защитой от DNS rebinding/SSRF.
- Проверка адреса `From` устраняет совпадение по подстроке, но не аутентифицирует отправителя: защита от поддельного
  настоящего адреса зависит от проверок SPF/DKIM/DMARC почтовым провайдером.
- Извлечение PDF остаётся обработкой недоверенного формата. Некоторые лимиты проверяются после распаковки;
  ограничение процесса и контейнера уменьшает последствия, но это не формальная гарантия отсутствия DoS.
- Секреты хранятся открытым текстом в приватном файле. Доступ root/владельца данных остаётся доверенным.
- Claude при наличии ключа получает текст подходящих чеков, как и раньше. Эта функция не отключена.
- В копии нет `.git`: отсутствие секретов в истории коммитов и на GitHub не проверено.
