## Находки

### 1. Высокий риск: открытое администрирование по умолчанию и передача сохранённого пароля на другой IMAP-сервер

Места: [main.py:394](../main.py#L394), [main.py:583](../main.py#L583), [imap_client.py:94](../imap_client.py#L94), [.env.example:23](../.env.example#L23).

`require_admin()` разрешает запрос, когда `ADMIN_TOKEN` пуст. Это исходная конфигурация. Любой клиент, имеющий сетевой доступ, может менять настройки и магазины, назначить собственный токен или запустить пересборку с подтверждением.

Есть дополнительное последствие: `test-imap` принимает другой публичный `IMAP_HOST`, но при отсутствующем в запросе пароле использует сохранённый `IMAP_PASSWORD`. Пока токен не установлен, посетитель может указать свой IMAP-сервер с корректным TLS-сертификатом и получить логин и пароль через IMAP LOGIN. Маскирование секретов в GET API от этого не защищает. Ограничение 5 попыток за 10 минут не предотвращает одну успешную передачу.

Подтверждение: без токена изменение настройки вернуло HTTP 200. При подменённых DNS и IMAP-соединении запрос с другим хостом и без пароля вызвал `login()` с сохранёнными фиктивными учётными данными. Реальные сетевые подключения не выполнялись.

Исправление: обязательная аутентификация до доступа к настройкам; первоначальная настройка через локальный доступ или одноразовый код. При смене назначения IMAP требовать повторный ввод пароля и не подставлять сохранённый пароль для произвольного хоста.

### 2. Высокий риск: расходы и запуск синхронизации доступны даже при установленном токене

Места: [main.py:485](../main.py#L485), [main.py:505](../main.py#L505), [main.py:526](../main.py#L526).

`/api/expenses`, `/api/stats`, `/api/categories`, `/api/stores` и `/api/runs` не используют `require_admin`. Пользователь без токена получает суммы, даты, состав покупок, магазины и журнал. Это документированное поведение, но для персонального трекера оно означает раскрытие данных всем, кто может обратиться к сервису.

`POST /api/sync` тоже открыт и не ограничен по частоте. Посторонний может повторно запускать получение почты и обработку, занимая общий lock и ресурсы. Вызовы Claude возможны, когда обрабатываемые письма требуют соответствующего парсера; повторный запрос не обязательно означает новый платный вызов из-за дедупликации. Проверки Origin для этого маршрута нет.

Подтверждение: при установленном токене `/api/settings` вернул 401, перечисленные GET-маршруты вернули 200, а в ответе расходов находилась искусственная покупка. POST синхронизации без токена и с посторонним Origin вернул 200 и вызвал подменённый `run_sync`.

Исправление: защищать все персональные данные и операции общей политикой доступа; отдельно ограничить частоту синхронизации. Для мониторинга оставить только минимальную проверку живости без журнала и деталей почты. Проверка через TestClient подтверждает принятие Origin сервером; поведение конкретного браузера и его ограничений доступа к локальной сети не тестировалось.

### 3. Высокий риск: ошибка чтения секретов отключает аутентификацию

Места: [settings.py:31](../settings.py#L31), [settings.py:77](../settings.py#L77), [main.py:394](../main.py#L394).

При повреждённом JSON или ошибке чтения `_load()` заменяет секреты пустым словарём. Если токен был задан только через UI и в окружении нет `ADMIN_TOKEN`, `cfg.get()` возвращает пустую строку, а `require_admin()` разрешает доступ. Сообщение об ошибке в health не блокирует административные методы.

Подтверждение: с корректно сохранённым фиктивным токеном GET настроек возвращал 401. После имитации некорректного JSON и сброса кеша GET настроек и создание магазина без токена вернули 200. Условие проявляется при загрузке файла, например после перезапуска или `invalidate()`; само повреждение не сбрасывает уже загруженный кеш. Наличие независимого токена в окружении предотвращает именно этот вариант отключения защиты.

Исправление: при ошибке чтения или проверки структуры секретов запрещать административные запросы и возвращать ошибку конфигурации; восстановление доступа выполнять локально. Не интерпретировать недоступность хранилища как разрешение анонимного доступа.

### 4. Высокий риск: настройка паролей и передача токена по HTTP

Места: [docker-compose.yml:5](../docker-compose.yml#L5), [Dockerfile:10](../Dockerfile#L10), [docs/DEPLOY.md:62](DEPLOY.md#L62), [static/settings.html:119](../static/settings.html#L119).

Compose публикует порты 80 и 8080 на всех интерфейсах. Uvicorn запущен без TLS, а основная инструкция предлагает вводить пароль почты и ключи на `http://<server-ip>/settings`. При таком доступе сетевой наблюдатель может прочитать пароль и токен, а активный посредник может подменить страницу. Проверка TLS у исходящего IMAP-соединения не защищает участок браузер -> веб-приложение.

Подтверждение: конфигурация и инструкция; сетевой перехват и работающий сервер не проверялись. В документации уже упомянут reverse proxy с TLS, но он не входит в конфигурацию по умолчанию.

Исправление: публиковать приложение на `127.0.0.1:8080:8080`, убрать прямой внешний порт 80 и использовать HTTPS с обязательной аутентификацией на proxy либо защищённый туннель. За proxy не оставлять второй открытый порт для обхода его защиты.

### 5. Высокий риск: достижимая CVE-2025-62727 в Starlette

Места: [requirements.txt:1](../requirements.txt#L1), [main.py:391](../main.py#L391), [main.py:400](../main.py#L400).

Чистая установка зависимостей на Python 3.12.14 разрешила `starlette==0.41.3`. `fastapi==0.115.6` требует `starlette>=0.40.0,<0.42.0`, поэтому обычная переустановка не подтянет исправленную версию.

В затронутых версиях обработка специально сформированного `Range` в `FileResponse` имеет квадратичную сложность. Приложение использует и `FileResponse`, и `StaticFiles`, доступные без токена. [Сообщение разработчика: CVE-2025-62727, исправление в 0.49.1](https://github.com/Kludex/starlette/security/advisories/GHSA-7f5h-v6xp-fcq8).

Подтверждение: запрос небольшого диапазона к `/static/i18n.js` без токена вернул 206 и достиг `_parse_range_header`. Ограниченная локальная проверка проблемной строки длиной 2/4/8 тысяч символов заняла примерно 0.025/0.099/0.395 секунды. Это подтверждает рост затрат; нагрузочная атака на сервер не проводилась.

Исправление: обновить совместимую пару FastAPI/Starlette и зафиксировать разрешённые зависимости. Для всех семи обнаруженных advisory минимальная указанная исправленная версия Starlette достигает 1.3.1; совместимость выбранного FastAPI нужно проверить отдельно. До обновления можно отклонять `Range` на proxy или выдавать статику отдельным сервером.

### 6. Средний риск: подмена магазина через строку From

Места: [imap_client.py:190](../imap_client.py#L190), [imap_client.py:212](../imap_client.py#L212), [imap_client.py:228](../imap_client.py#L228).

Отправитель сопоставляется по вхождению подстроки во весь From. Например, отображаемое имя с `wolt.com` при адресе на другом домене проходит `match_store()`. В извлечённой почте нет последующей проверки аутентичности отправителя; `uid_store` также служит запасным назначением магазина.

Подтверждение: искусственный From с чужим адресом и названием магазина в отображаемом имени совпал с магазином; переданный после этого фиктивный чек был записан. Если такое письмо доставлено в просматриваемую папку и попало в IMAP-выборку, возможны ложные расходы и передача его текста в Claude при соответствующей настройке. Прохождение фильтров реального почтового провайдера не проверялось.

Исправление: разбирать адрес через `parseaddr`, сравнивать точные адреса либо домены с корректной границей поддомена, повторно проверять отправителя после IMAP-поиска. Для проверки SPF/DKIM/DMARC доверять только результатам, сформированным собственным почтовым провайдером; произвольный присланный заголовок не является доказательством.

### 7. Средний риск: нет общего лимита памяти для писем и PDF

Места: [imap_client.py:50](../imap_client.py#L50), [imap_client.py:64](../imap_client.py#L64), [imap_client.py:217](../imap_client.py#L217), [imap_client.py:238](../imap_client.py#L238), [docker-compose.yml](../docker-compose.yml).

Письмо загружается целиком через RFC822; вложения декодируются, PDF разбираются по всем страницам. Ограничения `body[:30000]` и `pdf_text[:60000]` применяются после этих действий. Нет прикладного лимита размера письма, количества/совокупного размера вложений и страниц, количества писем за синхронизацию или лимита памяти контейнера.

Большое или специально подготовленное письмо способно занять память до срабатывания общего таймаута процесса. [Документация pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) отдельно предупреждает о значительном расходе памяти при извлечении текста. Это вывод по коду и документации; исчерпание памяти намеренно не воспроизводилось.

Исправление: проверять RFC822.SIZE до полного получения, ограничивать число и размеры сообщений/вложений и страниц, обрабатывать письма порциями; задать ограничения памяти и CPU для изолированного обработчика. Сохранить имеющийся механизм таймаута и регистрации проблемного письма.

### 8. Средний риск: JSON разбирается до проверки токена без ограничения размера запроса

Места: [main.py:538](../main.py#L538), [main.py:583](../main.py#L583), [docker-compose.yml](../docker-compose.yml).

Зависимость `require_admin` выполняется после чтения и разбора тела запроса внутри FastAPI. В приложении нет middleware, ограничивающего тело, а proxy с таким лимитом не включён в поставку. Поэтому даже неверный токен не предотвращает затраты памяти на большие JSON-запросы к административным маршрутам.

Подтверждение: под наблюдением `Request.json` неавторизованный запрос с полем длиной 64 KiB был полностью разобран до возврата 401. Полноценный DoS не воспроизводился; проверен порядок обработки, а отсутствие общего лимита установлено по коду.

Исправление: ограничивать размер тела на proxy или ASGI-уровне до JSON-разбора, включая запросы без Content-Length; при возможности выполнять аутентификацию до чтения тела. Ограничения отдельных полей дополняют, но не заменяют этот предел.

### 9. Средний риск: временный файл секретов сначала создаётся с правами umask

Место: [settings.py:174](../settings.py#L174).

`secrets.json.tmp` создаётся обычным `open(..., 'w')`, в него записываются секреты, и только потом вызывается `chmod(0600)`. При umask 022 файл уже содержит секреты с правами 0644. Если родительские каталоги доступны другим локальным пользователям, существует окно чтения; авария до chmod может оставить такой временный файл.

Подтверждение: в отдельном процессе с umask 022 режим непосредственно перед chmod был 0644, после замены итоговый файл имел 0600. Проверка использовала приватный временный каталог, поэтому фактическая кража другим OS-пользователем не выполнялась.

Исправление: создавать временный файл с 0600 сразу, например через `tempfile.mkstemp` в том же каталоге; сохранять атомарную замену и удалять остатки при ошибках. Каталог данных создавать с ограниченными правами. Для базы и резервных копий также явно задать права: они содержат финансовые данные и фрагменты писем.

## Результат поиска секретов

- В `.env.example` значения `IMAP_PASSWORD`, `ANTHROPIC_API_KEY` и `ADMIN_TOKEN` пусты.
- Найденные строковые пароли в `tests/support.py` и `tests/test_api.py` являются фиктивными тестовыми значениями; реальный IMAP в этих тестах запрещён заглушкой.
- detect-secrets: совпадения вручную проверены, это тексты интерфейса/диагностики и тестовые значения. Ключи, приватные ключи и токены известных форматов не обнаружены; проверка действительности возможных ключей во внешних сервисах отключена.
- `.gitignore` и `.dockerignore` исключают `.env` и `data`; это не доказывает отсутствие секретов в прошлых коммитах. В данной копии история отсутствует.
- При работе приложения IMAP-пароль, ключ Claude и административный токен сохраняются в открытом JSON в `data/secrets.json`, с итоговым режимом 0600. Это секреты времени выполнения, не хардкод в исходниках. Права доступа не являются шифрованием; доступ к диску/резервной копии с этим файлом раскрывает значения.
- Штатный GET настроек возвращает для секретов только признаки наличия. База и её штатные копии не включают отдельный файл секретов, но содержат покупки и текст почты.

Для остальных 23 разрешённых пакетов известных проблем этот запуск не показал. Системные пакеты Docker и загружаемый через CDN JavaScript этим Python-сканированием не покрываются. Отдельный запрос к OSV API для npm-пакета `chart.js@4.4.1` вернул пустой результат: известных advisory по этому запросу не найдено; целостность реально выдаваемого CDN-файла не проверялась.

## Дополнительные замечания

- [Dockerfile](../Dockerfile) не задаёт USER, контейнер работает от root. Для ограничения последствий компрометации нужен отдельный пользователь с доступом только к каталогу данных.
- [static/index.html:6](../static/index.html#L6) загружает Chart.js с CDN без SRI; при подмене ресурса скрипт исполняется с правами origin приложения. Токен UI хранится в sessionStorage того же origin. Подмены CDN или подтверждённой XSS не обнаружено; локальная поставка библиотеки или SRI уменьшат зависимость от CDN.
- При включённом Claude текст подходящих писем/чеков и названия товаров передаются Anthropic: [expense_parser.py:299](../expense_parser.py#L299), [translate.py:124](../translate.py#L124). Это описанная функция, но её нужно учитывать при работе с приватной почтой.
- `_host_allowed()` разрешает сохранённый хост без проверки приватного адреса и проверяет DNS отдельно от фактического соединения. Не считать этот метод полноценной защитой от SSRF. Обход через реальный DNS rebinding не тестировался.
- Bandit выдал 7 замечаний. SHA-1 здесь служит отпечатком для дедупликации, а не хранением паролей; bidi-символы находятся в regex удаления таких символов; `secret: True` является метаданными, а перехваты ошибок относятся к logout. Эти результаты не засчитаны как подтверждённые уязвимости.
- SQL-запросы с пользовательскими значениями используют ORM/параметры; форматируемые SQL миграций берут имена из констант. Подтверждённых SQL injection, выполнения shell-команд из пользовательского ввода и XSS при выводе текста писем не найдено. Это результат ограниченного аудита, не доказательство отсутствия всех уязвимостей.
